\section{Intentions}

\subsection{Definition and Role}

In the Deliveroo agent, intentions represent the agent's chosen commitments—the plans it is actively pursuing. While desires are possible goals the agent might want to achieve, intentions are selected desires that have been turned into concrete, executable actions. These intentions guide the agent's behavior over time and are at the core of its deliberative process.

The intention system serves as the bridge between high-level goals (desires) and low-level actions (actuator commands), providing a structured approach to goal commitment and execution in dynamic environments.

\subsection{Intention Types and Architecture}

The agent supports several distinct intention types, each designed for specific behavioral patterns:

\begin{itemize}
    \item \texttt{MOVE}: Navigate to a specific position using pathfinding
    \item \texttt{PICK\_UP}: Execute parcel pickup at the current location
    \item \texttt{PUT\_DOWN}: Drop carried parcels at delivery points
    \item \texttt{DELIVER}: Combined movement and delivery action
    \item \texttt{EXPLORE}: Investigate unexplored areas of the environment
    \item \texttt{PICKUP\_HANDOFF}: Coordinate parcel handoff with other agents
\end{itemize}

Each intention encapsulates not only the action type but also contextual information such as target positions, execution paths, and collaboration metadata.

\subsection{Priority-Based Intention Management}

The intention system employs a sophisticated priority queue mechanism to manage multiple competing goals:

\paragraph{Priority Queue Architecture}
Intentions are organized in a priority queue where higher-priority intentions are executed first. The priority calculation considers both the original desire priority and the intention type, ensuring critical actions (e.g., urgent pickups) take precedence over routine activities (e.g., exploration).

\subsection{Execution Loop and Control Flow}

The intention execution follows a control loop that balances reactivity with commitment. It shown by Algorithm~\ref{alg:intention-processing}.

\begin{algorithm}[htbp!]
	\DontPrintSemicolon
	\label{alg:intention-processing}
	\caption{Enhanced Intention Processing Loop}
	\While{agent is active}{
		\If{intention queue is empty OR current intention should be abandoned}{
			$intention \gets$ poll highest-priority intention from queue\;
			synchronize intention with current state\;
		}
		
		\If{current intention exists}{
			\If{intention is no longer valid}{
				discard current intention\;
				\textbf{continue}\;
			}
			
			$success \gets$ execute(intention)\;
			
			\If{success}{
				reset failure counter\;
				\If{intention is complete}{
					remove intention\;
				}
			}
			\Else{
				increment failure counter\;
				\If{failure threshold exceeded}{
					mark related desire as failed\;
					discard intention\;
				}
			}
		}
	}
\end{algorithm}

\subsection{Intelligent Path Planning and Execution}

\paragraph{Dynamic Path Recalculation}
Moving intentions (MOVE, DELIVER, EXPLORE) incorporate pathfinding that adapts to environmental changes. When the planned path becomes blocked by other agents or obstacles, the system automatically recalculates alternative routes without abandoning the overall intention.

\paragraph{Opportunistic Pickup Behavior}
During movement execution, the agent exhibits opportunistic behavior by automatically picking up parcels encountered along the path. This optimization reduces the need for separate pickup intentions and improves overall efficiency.

\subsection{Failure Handling and Recovery Mechanisms}

The intention system implements robust failure handling to maintain agent reliability:

\paragraph{Failure Classification}
The system distinguishes between different types of failures:
\begin{itemize}
    \item \textbf{Temporary failures}: Blocked paths, occupied positions
    \item \textbf{Permanent failures}: Unreachable destinations, invalid states
    \item \textbf{Context failures}: Outdated information, changed conditions
\end{itemize}

\subsection{Collaborative Intention Coordination}

\paragraph{Handoff Intention Management}
The system supports sophisticated handoff coordination through specialized PICKUP\_HANDOFF intentions. These intentions coordinate with other agents to optimize parcel delivery chains, considering factors such as:
\begin{itemize}
    \item Agent proximity and availability
    \item Delivery efficiency gains
    \item Communication overhead
    \item Coordination timing
\end{itemize}

\paragraph{Conflict Resolution}
The intention system includes mechanisms to detect and resolve conflicts with other agents, such as competing for the same parcel or delivery point. Priority-based resolution ensures fair resource allocation while maintaining system efficiency.

\subsection{State Synchronization and Validation}

\paragraph{Intention Validity Checking}
Before execution, each intention undergoes validity checking to ensure it remains relevant and executable:
\begin{itemize}
    \item Position-based validation for movement intentions
    \item Resource availability for pickup/delivery intentions
    \item Agent state consistency for all intention types
\end{itemize}

\paragraph{Context Synchronization}
The system continuously synchronizes intention context with the current world state, updating paths, targets, and execution parameters as environmental conditions change.

This comprehensive intention management system enables the agent to maintain goal-directed behavior while adapting to the dynamic nature of the delivery environment, balancing commitment with flexibility to achieve optimal performance.
